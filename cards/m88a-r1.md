# M88a (R1) — Pin QuickJS, inventory its platform surface, and approve bounded v1

- **Parent index:** M88, [#1915](https://github.com/drawmeanelephant/VirelaiOS/issues/1915).
- **Owner:** Sol 6.1, architecture/spec pass; Astra is also authorized by the index. Claude grounds the card before implementation; project owner reviews the decision.
- **Size / scheduling:** 8 agent hours, week one. Implementation is not part of this card.

## Deliverable

Land the index's complete R1 design gate in one ADR: an exact QuickJS version and commit, offline vendoring and update policy, an actual-source libc/POSIX inventory classifying every referenced symbol as provide, bounded-error stub, or feature refusal, the explicit v1 host API, numeric resource budgets, and the final independently closable M88b+ cards with disjoint ownership and verification. QuickJS is selected already; do not resurvey JS engines or build a new one. Script loading and printing/logging are the default host surface. Filesystem access from JS, sockets and timers require individual justification and budgets, not implicit access through a compatibility layer.

## Exclusive ownership

- Proposed new `docs/decisions/0039-quickjs-runtime.md`, including its budget, symbol-inventory and card-split tables.
- No implementation, shared SDK, build-system, status or gate-spec edits.
- Pin/source inspection and diagnostic outputs remain under ignored `artifacts/m88-r1/`. Do not commit an engine or a runnable port on this design card.

## Required design answers

1. Inspect the actual pinned source and its enabled/disabled translation units. Record source hashes, build configuration, each referenced platform symbol, every disposition and its reason. Distinguish engine core, optional library and tooling dependencies. Reconcile source inventory with any available freestanding compile/link diagnostics.
2. Name the Virelai-owned loading/logging contract, allocation/teardown and cancellation/error behavior. There is no DOM, browser API, `fetch`, npm, JIT, general libc or POSIX layer.
3. Pin an exact upstream version **and full commit**, license and source hashes. Choose an offline source layout, local patch policy, accountable update owner and revalidation policy. A version guess or build-time download cannot satisfy R1.
4. Resolve ADR 0030's no-cgo/no-FFI and bounded Zig-portfolio boundary explicitly with owner review. Do not quietly embed C/Zig into a Go app, add a new top-level `user/src/*.zig` app, or expand the kernel.
5. Finalize M88b/c or replace their shapes with independently landable cards. Assign every edited file and spec to exactly one card. Specify an on-guest file-eval proof, interactive-eval proof and executable refusal cases.

### Proposed numeric budgets, not measured results

These are reviewable starting ceilings, not claims about QuickJS. The merged R1 must approve or replace them with numeric values and report the exact inventory counts; none may remain unresolved.

| Required budget | Draft ceiling |
|---|---:|
| Engine binary bytes added, against the same empty host adapter/build configuration | 1,572,864 bytes |
| Heap per context, including engine allocations | 4,194,304 bytes |
| Cold first eval, accepted guest launch through first successful result, no prewarmed context | 5,000 ms |
| Simultaneous contexts | 1 |
| Provided shim symbols, count ceiling | 48 |
| Bounded-error stub symbols, count ceiling | 16 |
| Refused symbol/feature entries, count ceiling | 32 |
| Script source bytes | 1,048,576 bytes |
| Evaluation interruption deadline, including an infinite-loop refusal | 5,000 ms |

The three shim numbers are **planning caps, not an invented inventory**. R1 must also publish the three exact counts from the pinned source, reconcile every reference, and explain any cap change. Count aliases and disabled-source references consistently. Reference hardware for the proposed timing ceiling: Apple M4, 16 GiB host RAM, macOS 27.2, Apple VZ, 2 vCPUs and 256 MiB guest RAM. Record build mode, timing boundaries and host load; evaluate the maximum of five fresh-process samples, not an average hiding an outlier. The two additional limits prevent a hostile script from defeating the heap ceiling; R1 must define and justify their enforcement, including interruption precision on the existing guest clock.
