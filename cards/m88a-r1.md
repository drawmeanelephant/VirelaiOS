# M88a (R1) — Pin QuickJS, inventory its platform surface, and approve bounded v1

- **Parent index:** M88, [#1915](https://github.com/drawmeanelephant/VirelaiOS/issues/1915).
- **Owner:** Sol 6.1, architecture/spec pass; Astra is also authorized by the index. Claude grounds the card before implementation; project owner reviews the decision. drawmeanelephant, ADR 0030's Zig Guest Target/Backend Owner, approves the native-program amendment this card requires.
- **Size / scheduling:** 8 agent hours, week one. Implementation is not part of this card.

## Deliverable

Land the index's complete R1 design gate in one ADR: an exact QuickJS version and commit, offline vendoring and update policy, an actual-source libc/POSIX inventory classifying every referenced symbol as provide, bounded-error stub, or feature refusal, the explicit v1 host API, numeric resource budgets, and the final independently closable M88b+ cards with disjoint ownership and verification. Land with it the owner-approved ADR 0030 amendment that admits this native program (item 4). QuickJS is selected already; do not resurvey JS engines or build a new one. Script loading and printing/logging are the default host surface. Filesystem access from JS, sockets and timers require individual justification and budgets, not implicit access through a compatibility layer.

## Required design answers

1. Inspect the actual pinned source and its enabled/disabled translation units. Record source hashes, build configuration, each referenced platform symbol, every disposition and its reason. Distinguish engine core, optional library and tooling dependencies. Reconcile source inventory with any available freestanding compile/link diagnostics. Start from the existing observation: ADR 0028 Amendment A recorded bellard/quickjs `04be246` (`quickjs.c` 2,033,048 B) failing a freestanding compile on libc headers (`inttypes.h` `include_next`), and MicroQuickJS `203d5bb` at 666,384 B as a native `-Os` object.
2. Name the Virelai-owned loading/logging contract, allocation/teardown and cancellation/error behavior. There is no DOM, browser API, `fetch`, npm, JIT, general libc or POSIX layer.
3. Pin an exact upstream **and full commit**: name the tree (bellard/quickjs, which ADR 0028 measured, or a named fork), license and source hashes. The repository is proprietary (`LICENSE`), and ADR 0028 refused to vendor AGPL Elk on that ground; record the pinned tree's license. Choose an offline source layout, local patch policy, accountable update owner and revalidation policy. A version guess or build-time download cannot satisfy R1.
4. **ADR 0030 boundary (binding).** QuickJS is C. Go cannot link it: ADR 0030 has no cgo or FFI, and D3 forbids importing a C ABI. The remaining route is a native AArch64 EL0 program. ADR 0030 A1 is a closed exception for four named workloads, and "adding another program requires another owner-approved ADR amendment" (`0030:366`). ADR 0038's recipe covers Zig sources, not C translation units. This R1 therefore drafts that ADR 0030 amendment, with A1.2-shaped limits, and states how C sources build under the native target. It cannot close without the approved amendment. Also excluded: embedding C/Zig into a Go app, a C-to-Go transpile that carries an emulated libc (a second libc), a native app outside the amendment, and kernel expansion.
5. **JS boundaries already decided.** ADR 0028 D2 keeps JavaScript out of the HTML renderer (`WEB.ELF`) permanently. Amendment A closed JS-in-`WASM.BIN` under the frozen interpreter caps. This runtime is a standalone program: never wired into WEB, and it does not reopen the WASM route.
6. Finalize M88b/c or replace their shapes with independently landable cards. Assign every edited file and spec to exactly one card, written in coordination-gate syntax: exact paths or `dir/*` prefix globs. The gate does not expand `**`, so a `dir/**` token never matches a real path (`tools/status/verify-issue-coordination.sh:89-101`). Place code in an ADR-legal home: an allowlisted adapter under `user/src/` reusing the `user/zig/` SDK (`0038:81-88`), unless the amendment names another path. Specify an on-guest file-eval proof, interactive-eval proof and executable refusal cases.

### Proposed numeric budgets, not measured results

These are reviewable starting ceilings, not claims about QuickJS. The merged R1 must approve or replace them with numeric values and report the exact inventory counts; none may remain unresolved.

| Required budget | Draft ceiling |
|---|---:|
| Engine binary bytes added, against the same empty host adapter/build configuration | 1,572,864 bytes |
| Heap per context, including engine allocations | 4,194,304 bytes |
| Cold first eval, accepted guest launch through first successful result, no prewarmed context | 5,000 ms |
| Simultaneous contexts | 1 |
| Provided shim symbols, count ceiling | 48 |
| Bounded-error stub symbols, count ceiling | 16 |
| Refused symbol/feature entries, count ceiling | 32 |
| Script source bytes | 1,048,576 bytes |
| Evaluation interruption deadline, including an infinite-loop refusal | 5,000 ms |
| Native stack use, with QuickJS's own C-stack limit set below the 192 KiB native user stack (`kernel/src/scheduler.zig:142`) | 131,072 bytes |
| Output bytes per script run (slot 1 accepts at most 256 B per write) | 65,536 bytes |
| Open file handles per process (kernel limit 8): script input plus one log/receipt file | 2 |

The three shim numbers are **planning caps, not an invented inventory**. R1 must also publish the three exact counts from the pinned source, reconcile every reference, and explain any cap change. Count aliases and disabled-source references consistently. If `Math` is supported, libm entry points alone may approach the provided cap (inference, not a count). Reference hardware for the proposed timing ceiling: Apple M4, 16 GiB host RAM, macOS 27.2, Apple VZ, 2 vCPUs and 256 MiB guest RAM. Record build mode, timing boundaries and host load; evaluate the maximum of five fresh-process samples, not an average hiding an outlier.

The script-size and interruption limits prevent a hostile script from defeating the heap ceiling; R1 must define and justify their enforcement, including interruption precision on the existing guest clock. A 1 MiB script must either compile inside the 4 MiB heap or fail as a named refusal; R1 measures which. ADR 0030 A1.2 requires native workloads to state input/output bytes, heap and stack use, open handles, argv/env and path lengths. Argv/env and path lengths inherit ADR 0038's limits (seven user arguments, 64-byte raw paths). Every process also shares 4,096 recorded demand pages (about 16 MiB) and 16 mmap regions (`kernel/src/process.zig:124-130`); heap plus engine data must fit inside them.
