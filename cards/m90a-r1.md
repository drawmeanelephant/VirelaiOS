- **Parent index:** M90, [#1917](https://github.com/drawmeanelephant/VirelaiOS/issues/1917).
- **Owner:** Sol 6.1, architecture/spec pass; Astra is also authorized by the index. Claude grounds the draft; project owner reviews the decision.
- **Size / scheduling:** 8 agent hours, week one. Schedule before M89a to give its downstream PDF survey a concrete interface.

## Deliverable

Land the index's complete SVG R1 in one ADR: a no-libc/no-POSIX renderer survey, exact element/attribute subset and per-case exclusion behavior, numeric binary/time/memory/canvas budgets, explicit text policy, the function-level vector-raster contract offered to M89 and a reviewed disjoint, closable implementation breakdown. Survey the index's nanosvg-class embedding and from-scratch Zig subset honestly, plus the Go route in item 1; do not evaluate Rust or quietly choose an engine now. SVG parsing and shared vector rasterization are distinct contracts. No filters, animation, scripting, external-resource loading or viewer UI is included.

## Required design answers

1. Assess actual candidate source/dependency/license weight against the target, and compare the routes under ADR 0030:
   - **Go under `user/go/`.** Needs no ADR change (ADR 0030 D2). Prior art: `user/go/ttf/raster.go` already rasterizes flattened contours to an anti-aliased non-zero-winding coverage mask, and `user/go/ttf/outline.go` flattens quadratic curves. `user/go/draw` provides bounded shape primitives. Assess this route, or record the owner's explicit exclusion of it.
   - **nanosvg-class C embedding, or a from-scratch Zig renderer.** Both are new native programs. #1917 says the Zig route "fits the Zig portfolio", but ADR 0030 A1 is a closed four-workload allowlist: "adding another program requires another owner-approved ADR amendment" (`0030:228-236,366`). Choosing either route means this R1 drafts that amendment for owner approval. Go cannot link C or Zig (D3).
   Existing Go AA primitives are prior art, not proof of a general vector renderer.
2. Declare every supported element, attribute, path/fill/transform rule and excluded case. Pick bounded refusal or graceful degradation per exclusion; forbid silent invented rendering and external resources.
3. Approve all four required numeric budgets below, their accounting and workload definitions; also bound XML/path/source complexity and total work.
4. State `<text>` behavior: the index permits the virelai-sans path, refusal or substitution. Observed: Virelai Sans is not shipped in `image/fonts/`, which holds Inter, Fira Code and the VirelaiChrome icon font. `user/go/icons/generate.py:2-9` reads Virelai Sans from an external pipeline. The in-tree text path is `user/go/ttf` with Inter or Fira Code. Do not infer a usable font path from a name in the issue.
5. Publish a **function-level** “rasterize this vector description” interface for M89: representations, coordinates, pixel format/stride/alpha, buffer/scratch ownership, errors, supported operations and budget responsibilities. M89 never edits or reaches into M90 files. Two constraints bind it:
   - A function-level call works only in-process, within one language (ADR 0030 D3 forbids cross-language linkage), so this choice fixes M89's engine language. State that consequence explicitly.
   - The 1,024 × 1,024 limit below is the SVG front end's canvas limit. The vector contract states its own maximum target size, which must cover M89a's proposed 1,024 × 1,536 page, or define tiling.
6. Decide language/ABI boundaries against ADR 0030's no-FFI rule and the bounded native SDK. Finalize the M90b/c shapes and consumer-side contract test, without depending on PDF implementation landing. Write every reservation in coordination-gate syntax: exact paths or `dir/*` prefix globs. The gate does not expand `**` (`tools/status/verify-issue-coordination.sh:89-101`).

### Proposed numeric budgets, not measured results

R1 can revise the values with reasons; the merged gate must have a numeric value for every required limit.

| Required budget / additional hostile-input limit | Draft ceiling |
|---|---:|
| Renderer binary bytes added versus equivalent empty adapter | 1,048,576 bytes |
| Typical icon rasterization, 64 × 64 output pixels, including parse | 100 ms |
| Peak raster memory, including source, output and scratch | 8,388,608 bytes |
| Supported canvas dimensions | 1,024 × 1,024 pixels maximum |
| SVG source size | 1,048,576 bytes |
| XML nesting depth | 32 |
| Total path segments after expansion | 8,192 |
| Work units per render, defined by R1 | 1,000,000 |

Reference hardware: Apple M4, 16 GiB host RAM, macOS 27.2, Apple VZ, 2 vCPUs and 256 MiB guest RAM. Time the parse/raster call, excluding VM startup and input transport; report maximum corpus icon time, build mode and host load. R1 defines a finite representative icon corpus and maximum-canvas tests, timing precision and an allocation plan within the existing target's limits. Every process shares 4,096 recorded demand pages (about 16 MiB) and 16 mmap regions (`kernel/src/process.zig:124-130`). On a Go route, runtime and collector headroom sit inside the same cap as the 8 MiB peak. Numbers are proposed ceilings, not measurements or approval of an element subset.
