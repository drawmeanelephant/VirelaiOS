# M90a (R1) — Choose the SVG subset renderer and publish the PDF-facing vector contract

- **Parent index:** M90, [#1917](https://github.com/drawmeanelephant/VirelaiOS/issues/1917).
- **Owner:** Sol 6.1, architecture/spec pass; Astra is also authorized by the index. Claude grounds the draft; project owner reviews the decision.
- **Size / scheduling:** 8 agent hours, week one. Schedule before M89a to give its downstream PDF survey a concrete interface.

## Deliverable

Land the index's complete SVG R1 in one ADR: a no-libc/no-POSIX renderer survey, exact element/attribute subset and per-case exclusion behavior, numeric binary/time/memory/canvas budgets, explicit text policy, the function-level vector-raster contract offered to M89 and a reviewed disjoint, closable implementation breakdown. Survey nanosvg-class embedding and a from-scratch Zig subset honestly; do not evaluate Rust or quietly choose an engine now. SVG parsing and shared vector rasterization are distinct contracts. No filters, animation, scripting, external-resource loading or viewer UI is included.

## Exclusive ownership

- Proposed new `docs/decisions/0041-svg-raster.md`, including its shared-vector interface and card split.
- No PDF ADR, implementation, status or gate-spec edits.
- Candidate inspection/diagnostics remain under ignored `artifacts/m90-r1/`; no renderer lands here.

## Required design answers

1. Assess actual candidate source/dependency/license weight against the target; explicitly compare minimal embedding and a Zig subset. Existing Go AA primitives are prior art, not proof of a general vector renderer.
2. Declare every supported element, attribute, path/fill/transform rule and excluded case. Pick bounded refusal or graceful degradation per exclusion; forbid silent invented rendering and external resources.
3. Approve all four required numeric budgets below, their accounting and workload definitions; also bound XML/path/source complexity and total work.
4. State `<text>` behavior: the index permits the virelai-sans path, refusal or substitution. Audit actual font availability and interfaces before selecting. Do not infer a usable font path from a name in the issue.
5. Publish a **function-level** “rasterize this vector description” interface for M89: representations, coordinates, pixel format/stride/alpha, buffer/scratch ownership, errors, supported operations and budget responsibilities. M89 never edits or reaches into M90 files.
6. Decide language/ABI boundaries against ADR 0030's no-FFI rule and the bounded native SDK. Finalize the M90b/c shapes and consumer-side contract test, without depending on PDF implementation landing.

### Proposed numeric budgets, not measured results

R1 can revise the values with reasons; the merged gate must have a numeric value for every required limit.

| Required budget / additional hostile-input limit | Draft ceiling |
|---|---:|
| Renderer binary bytes added versus equivalent empty adapter | 1,048,576 bytes |
| Typical icon rasterization, 64 × 64 output pixels, including parse | 100 ms |
| Peak raster memory, including source, output and scratch | 8,388,608 bytes |
| Supported canvas dimensions | 1,024 × 1,024 pixels maximum |
| SVG source size | 1,048,576 bytes |
| XML nesting depth | 32 |
| Total path segments after expansion | 8,192 |
| Work units per render, defined by R1 | 1,000,000 |

Reference hardware: Apple M4, 16 GiB host RAM, macOS 27.2, Apple VZ, 2 vCPUs and 256 MiB guest RAM. Time the parse/raster call, excluding VM startup and input transport; report maximum corpus icon time, build mode and host load. R1 defines a finite representative icon corpus and maximum-canvas tests, timing precision and an allocation plan within the existing target's limits. Numbers are proposed ceilings, not measurements or approval of an element subset.
